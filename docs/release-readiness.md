## LaunchServices and test bundles

On this machine (macOS 26.6.2) `lsregister -u <bundle>` does not last while the bundle exists: within a second LaunchServices registers it again, flagged `launch-disabled`, and it is still what `NSWorkspace` resolves `dev.dak.polygloss` and `polygloss://` to. Only unregistering it and then deleting it removes it for good (checked: the deleted test bundle stayed out of `lsregister -dump`). So `scripts/test-e2e.sh` now deletes its default test bundle (`<target>/bundle-e2e.noindex/Polygloss.app`) after unregistering it, pass or fail (test `the default test bundle is deleted after the run, pass or fail`); a caller-provided `POLYGLOSS_DIST_DIR` is left alone. After the gate, the slot-1 `dist/` bundle was unregistered and deleted. One stale bundle from another task remains registered, launch-disabled: `/Users/dak/projects/polygloss-wt/slot-3/dist/Polygloss.app` (left for the user, item 8).
