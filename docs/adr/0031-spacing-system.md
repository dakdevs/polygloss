# ADR-0031: Spacing system

- **Status:** Accepted. Amends [ADR-0027](0027-polygloss-themes-and-card-layout.md)'s card numbers (16 pt sides → 12, the file header from 2.25 rows to row + 24 pt); the rest of ADR-0027 stands.
- **Date:** 2026-10-06
- **Design:** [§11.17 Spacing and layout](../design.md#1117-spacing-and-layout-adr-0031), [research: spacing audit](../research/spacing-audit.md)

## Context

The user asked for consistent padding and spacing, with a system that says how each value is calculated and when it is used. The audit found 493 hand-picked values in 47 files (110 raw `px(…)`, 222 rem helpers, 100 text presets, 8 literal line heights, 53 numeric geometry consts), plus painter arithmetic and struct-literal geometry in the viewport (`CardStyle::default`, `Metrics::default`). About 90% already fall on 2/4/6/8/12/16/24/32, but nothing decides which value a role gets: the sidebar has four left edges (8, 12, 16, 12), secondary bars are 30, 32, 34, 38 and 40 tall, radii are 3–12 plus capsules, header pills are radius 6 where the reference's are capsules, and the viewport sizes header and band columns in code-font advances (≈ 7.8 pt, fractional). Measured against the reference at 2×, the toolbar sits 4.5 pt off the card edge, cards are 16 pt from the sides (reference 12–13), and the file path and code start 17 pt and 16 pt left of the reference's shared columns. gpui's rem helpers resolve against gpui-component's `Theme.font_size` (16), so a change there would rescale every value. A probe on macOS 26.6 measured AppKit's control ladder (mini 16, small 20, regular 24, large 28, extra large 36), text fields 24, traffic lights 14 pt at x = 19, 42, 65 and system line heights 12 → 15, 13 → 16, 14 → 17, 15 → 18. Lucide icons are drawn on a 24-unit grid with a 2-unit stroke, so at 16 pt their ink starts 0.7–5.3 pt inside the box, by glyph (folder 0.7, search and panel-left 1.3, chevron-down 3.3, chevron-right 5.3). Details: [research: spacing audit](../research/spacing-audit.md).

## Decision

### Grid and scale

- **Grid:** 4 pt for layout (margins, gaps between components, heights). 2 pt half-steps only inside a component (icon–label gaps, pill and field insets, the segmented rim, the sidebar edge). Off the 2 pt grid only: the 1 pt border, the 2 pt focus ring and cursor bar, the 3 pt change bar.
- **Primitive scale** (`space::scale`, named after gpui's rem suffixes so migration is mechanical): `S0_5` 2, `S1` 4, `S1_5` 6, `S2` 8, `S2_5` 10, `S3` 12, `S3_5` 14, `S4` 16, `S5` 20, `S6` 24, `S7` 28, `S8` 32, `S9` 36, `S10` 40, `S11` 44, `S13` 52. Only token modules use it; call sites use the semantic tokens below, and every value a call site needs has one.
- **Units:** absolute points (`f32`, written `px(space::…)`), never rem. A test pins `Theme.font_size` at 16 for the kit's own internals.

### Alignment

Columns are defined by boxes. Ink lands where each glyph's own inset puts it; the reference's ink measurements and our expected ink are both in the reference-edges table below.

- **M1, main column:** one edge E = `CANVAS` 12 from each side holds the toolbar's first content box and its last control's right edge, the banner strip's content, both outer edges of every card, and the space below the last card. Cards are `gap::CARDS` 12 apart. The first card (the header card, else the first file card) starts at the banner strip's bottom edge, 0 pt below it: the 32 pt strip is the canvas above it (D4, OQ-39).
- **M2, traffic lights:** the toolbar's leading inset while the sidebar is hidden is derived, 19 + 3 · 14 + 2 · 9 + 9 = 88 (one light gap after the zoom button); its show-sidebar button sits there and the first item `SM + CONTROLS` later (120); fullscreen uses `CANVAS`. During a sidebar motion ADR-0030's Panels rule moves them.
- **M3, bars:** every bar centres its items; the top rows hold SM 24 pills and buttons and MD 28 segmented tracks.
- **C1, card columns** (from the card's inner left edge): the 3 pt change bar, then the number columns, each right-aligned in a `digits · advance` cell: `gutter(digits, advance, columns) = max(GUTTER_MIN, ceil4(CHANGE_BAR + NUMBER_PAD_L + columns · digits · advance + (columns − 1) · NUMBER_GAP + NUMBER_PAD_R))`, one minimum and one `ceil4` over the total; `columns` is 1 for a one-sided card and for each split half, 2 for unified (old, then new, `NUMBER_GAP` apart). At 13 pt (advance 7.8): one column 40 up to 3 digits, 48 for 4, 56 for 5, 64 for 6; unified 72 for 3 digits, 88 for 4. Code starts at `gutter + CODE_PAD` in bars and none modes (50 for a one-column gutter up to 3 digits; 82 unified at 3 digits); in `+-` mode the indicator's cell (2 advances, it holds a code glyph) replaces `CODE_PAD`, so code starts at `gutter + 2 · advance` (55.6 at 13 pt, 3 digits).
- **C2, file header:** the chevron box at `CHEVRON_X` 10 (its chevron-down ink then lands at 14.3 from the card's outer edge, the reference's 14–14.5); the path at `PATH_X` 40 in every card (paths align across cards; in a one-column card with ≤ 3-digit numbers it meets the gutter's end, as in the reference); trailing controls end `CARD_TRAILING` 8 from the inner right edge. Section bands put their chevron box at `CHEVRON_X` and their label at `PATH_X` from the card column's inner edge, so they align with file headers; gap-row links start at the code column, `GROUP` apart.
- **C3, header card:** avatar at `CARD_X` 16, `AVATAR_LG` = `CODE_X − CARD_X − CONTROLS` = 26, so the title starts at `CODE_X` 50: the code column of a one-column or split card up to 3 digits in bars or none mode. Wider gutters, unified and `+-` cards start their code further right; the title stays at 50. Height `CARD_Y + 20 + 18 + CARD_Y` = 54, plus its two borders = 56.
- **C4, inline blocks:** thread blocks and the composer sit `NESTED_X` 12 from the card's inner edges and `NESTED_Y` 8 apart vertically, radius MD.
- **S1–S4, sidebars:** fields, row highlights and cards sit `SIDEBAR` 10 from both edges (filter field, find input, tree, Reviews, accordion headers, find results, threads-panel cards). Inside a highlight or field, a leading icon box sits at 10 + `ICON_LEAD` = 16 and leading text without an icon at 10 + `TEXT` = 18; trailing icon boxes end at W − 16 and trailing text at W − 18. Plain text outside a highlight (the footer) sits on the `SIDEBAR` edge 10. The filter field's top is `TOP + RIM` = 54; tree depth adds `TREE_INDENT` 14. The sidebar's toggle is an SM button whose icon box ends at W − 16.
- **Scaling:** geometry that holds code text scales with the code row (rows; file header `row + 24`, 44 at 13 pt; gap row `row + 12`; placeholder `2 · row + 8`); geometry that holds UI text is fixed points (bands, pills, Viewed, icons, insets). `CARD_TRAILING` is fixed: it does not follow the header's height.
- **No layout shift:** changing numbers in the UI font (`N/M`, thread and draft counts, footer totals) use tabular figures or the code font; selected, hover and pressed states change color only, never weight or padding; conditional items have reserved slots or overlay.

| Dense       | Sidebars, threads panel, find pane, menus, overlay lists | MD 28 rows touching (SM 24 for leaf result lists); edge `SIDEBAR` (overlays `OVERLAY`); pane bars BAR 36; cards `CONTROLS` apart |

One surface, one density. Overlay rows' content column (`OVERLAY` + `TEXT` = 16) equals the dialog header inset (`CARD_X`). No user-facing density setting.

### Where tokens live and how they are enforced

- `polygloss_viewport::space` (the viewport paints the canvas and cards, and the app depends on it): the scale, semantic tokens, card columns and functions, text tokens and strokes, with invariant tests. Each group module exposes `ALL: &[(&str, f32)]`. Call sites write module-qualified paths (`height::SM`, `radius::SM`; groups are not glob-imported). `CardStyle::default()`, `Metrics::default()` and every viewport geometry constant read from it. `polygloss_app::space` re-exports it and adds `layout`: app-only sizes (top-row and panel widths, minimum widths, picker and dialog sizes, Home columns, toolbar give-way caps, the tree's Viewed slot). gpui-base's `SpacingTokens` and `RadiusTokens` are not used.
- gpui-component: radius SM, `radius_lg` LG; Buttons `.xsmall()` (20) or `.small()` (24) only; kit internals (Button, Input, ListItem, PopupMenu) keep their rem metrics at the pinned 16.
- `tests/scripts/spacing-tokens.test.ts` scans every `.rs` file `rg --files` lists under `crates/polygloss-app/src` and `crates/polygloss-viewport/src` (untracked files included). It strips comments and `#[cfg(test)]` items by brace matching (a `#[cfg(test)] mod x;` declaration strips only itself) and exempts the token modules (both `space.rs`; the viewport's `motion.rs`; the app's `motion.rs` and `motion/`). Rules:
  1. A bare number as the whole argument of `px`, `rems` or `relative` (except `px(0.)`), and any numeric literal other than 0, 1, 2 or 0.5 inside one.
  2. gpui rem spacing, size, inset and radius helpers (`p_2`, `gap_1p5`, `size_4`, `top_1`, `rounded_md`; `_0`, `_full`, `_auto`, fractions, `min_w_0` and `min_h_0` pass).
  3. Text presets (`text_xs` … `text_lg`, `text_base`) and any `line_height(` outside the text helper.
  4. Numeric `f32` or `Pixels` consts.
  5. Struct-literal geometry fields (`margin*`, `gap*`, `radius*`, `pad*`, `height*`, `width*`, `inset*`, `offset*` set to a number).
  6. In the viewport's painter files (a list in the lint; a viewport file that calls `paint_quad`, `paint_svg`, `paint_path` or `shape_line` and is not listed fails), float literals other than `0.0`, `1.0`, `/ 2.0` and `* 0.5`, except as arguments of `hsla`, `rgba`, `.alpha` and `.opacity`.
  7. A `Button::new(` chain without `.small()` or `.xsmall()`.
  8. `space::scale::` paths.
- The allow-list is path + exact snippet + reason (non-geometry consts and ratios, `perf/`, `dump.rs`); an entry that no longer matches fails. Failures read `path:line rule 'snippet' → space::<group> (ADR-0031)`, and for the debt map `spacing-debt.json[path]: N → M`.
- During M7 a per-file debt map ratchets: a file fails above its debt and below it, so each migration lowers the number. At each wave merge it is re-seeded (`UPDATE_SPACING_DEBT=1`), and the merge fails if any entry rises. M7's last task deletes the map.
- Invariant tests assert rules against independent sources: the grid, the probe's ladder, concentric radii, each group's `ALL` length against a count written in the test. They never restate token values. Reference tests measure ink on GPUI screenshots and assert `|measured − reference| ≤ allowed + 0.5` (the measurement's accuracy), with both numbers written in the test from the table below. `CardStyle::default()` and `Metrics::default()` are pinned to the reference's numbers at 13 pt (side margin 12, gap 12, file header 44).

## Consequences

- Every screenshot baseline changes; the M7 spacing tasks re-record theirs and the gate reviews all of them against the reference.
- The card's inner width changes, so the automatic split/unified threshold (160 ± 8 columns) is reached at different window widths; anchor tests and the §12.1 budgets are rerun. Header and band columns stop scaling with the code font.
- UI text gets even line heights instead of gpui's 1.618 default, so most single-line controls change height by a fraction of a point.
- The two segmented controls become one component; thread blocks, the composer and suggestion snippets reuse the card's gutter function instead of their own formulas.
- The reserved banner strip (OQ-39) and the tree's Viewed slot (OQ-43) keep their approved behavior; the alternatives are shown to the user at the M7 gate.
- New code in the files the lint covers cannot add a raw dimension without failing it; the viewport's painter files are covered by the float rule, and its two style defaults are pinned to the reference.

## Alternatives rejected

| Option                                                | Why not                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| gpui-base `SpacingTokens` / `RadiusTokens`            | No 6, 10 or 28 steps; the kit's components do not read them                                      |
| gpui rem helpers as the scale                         | They follow `Theme.font_size`; at a native 13 every value turns fractional (× 0.8125)            |
| A strict 8 pt grid                                    | Breaks AppKit's 20/28/36 and the reference's 12 pt gaps                                          |
| Pixel-matching the reference (13, 22, 30, 41.5, 56.5) | Odd values with no rule; each deviation is ≤ 2 pt and recorded above                             |
| One ink column for every sidebar icon                 | Lucide's ink insets differ by glyph (0.7–5.3 pt at 16 pt); boxes are the column, ink is recorded |
| A "canvas lead" token                                 | The banner strip is the canvas above the first card; cards start at its bottom edge              |
| 0.5 pt hairlines                                      | The reference's borders are 1 pt; half-point quads blur at 1×                                    |
| 44 pt hit targets                                     | A pointer-only macOS app; AppKit's regular control is 24 pt                                      |
| Header and band columns in code-font advances         | Fractional columns, and chrome that moves with the code font                                     |
| Per-crate token sets                                  | The app's header card, thread blocks and composer mirror geometry the viewport paints            |
| A lint in Rust (build script, clippy)                 | The repo's hygiene guards are bun tests; a text scan with fixtures is simpler                    |
| Shrink the banner strip now                           | Reverses D4 ("content never moves"); the user decides (OQ-39)                                    |
| A density setting                                     | Not asked for; the tokens make it possible later                                                 |
