# ADR-0031: Spacing system

- **Status:** Accepted. Amends [ADR-0027](0027-polygloss-themes-and-card-layout.md)'s card numbers (16 pt sides → 12, the file header from 2.25 rows to row + 24 pt, the 3 pt change bar → 4); the rest of ADR-0027 stands. Its card columns are the provisional answer to design OQ-56 (T6.16: the viewport's insets are tighter than the reference's), which the user confirms at the M7 gate.
- **Date:** 2026-10-06
- **Design:** [§11.17 Spacing and layout](../design.md#1117-spacing-and-layout-adr-0031), [research: spacing audit](../research/spacing-audit.md)

## Context

The user asked for consistent padding and spacing, with a system that says how each value is calculated and when it is used. The audit found 493 hand-picked values in 47 files (110 raw `px(…)`, 222 rem helpers, 100 text presets, 8 literal line heights, 53 numeric geometry consts), plus painter arithmetic and struct-literal geometry in the viewport (`CardStyle::default`, `Metrics::default`). About 90% already fall on 2/4/6/8/12/16/24/32, but nothing decides which value a role gets: the sidebar has four left edges (8, 12, 16, 12), secondary bars are 30, 32, 34, 38 and 40 tall, radii are 3–12 plus capsules, header pills are radius 6 where the reference's are capsules, and the viewport sizes header and band columns in code-font advances (≈ 7.8 pt, fractional). Measured against the reference at 2×, from its own 1 pt edges (the sidebar's divider, each card's border): the main column starts after a 1 pt divider at 280 pt; cards sit 12 pt inside it (Polygloss 16); the change bar is 4 pt (Polygloss 3); a file header's chevron, path and code ink start 15.5, 42 and 53 pt from the card's outer edge (Polygloss 8.5, 24.5 and ≈ 36: design OQ-56); the toolbar's first glyph sits 14.5 pt into the main column. gpui's rem helpers resolve against gpui-component's `Theme.font_size` (16), so a change there would rescale every value. A probe on macOS 26.6 measured AppKit's control ladder (mini 16, small 20, regular 24, large 28, extra large 36), text fields 24, traffic lights 14 pt at x = 19, 42, 65 and system line heights 12 → 15, 13 → 16, 14 → 17, 15 → 18. Lucide icons are drawn on a 24-unit grid with a 2-unit stroke, so their ink starts inside the box by the glyph's own inset (at 16 pt: folder 0.7, search and panel-left 1.3, chevron-down 3.3, chevron-right 5.3; at 14 pt: folder 0.6, search 1.2, file 1.8; at 12 pt: chevron-down 2.5). The reference's tree draws 12 pt chevrons and 14 pt folder and file icons. Details: [research: spacing audit](../research/spacing-audit.md).

## Decision

### Grid

- **Grid:** 4 pt for layout (margins, gaps between components, heights). 2 pt half-steps only inside a component (icon–label gaps, pill and field insets, the segmented rim, the sidebar edge). Off the grid only: the 1 pt border, and centring offsets computed as `(container − item) / 2`, which are derived, never written.
- **No primitive scale:** each value is written once, in its semantic group below; every value a call site needs has a semantic token.
- **Units:** absolute points (`f32`, written `px(space::…)`), never rem. A test pins `Theme.font_size` at 16 for the kit's own internals.

### Alignment

Columns are defined by boxes. Ink lands where each glyph's own inset puts it; the reference's ink and our expected ink are both in the reference-edges table below.

- **M1, main column:** the main column starts after the sidebar's 1 pt divider (at W + `BORDER` while the sidebar shows; the divider belongs to the sidebar's extent, ADR-0030 Panels), and ends at the threads panel's divider. One edge E = `CANVAS` 12 from each side holds the toolbar's first content box and its last control's right edge, the banner strip's content, both outer edges of every card, and the space below the last card. Cards are `gap::CARDS` 12 apart. The first card (the header card, else the first file card) starts at the banner strip's bottom edge, 0 pt below it: the 32 pt strip is the canvas above it (D4, OQ-39).
- **M2, traffic lights:** the toolbar's leading inset while the sidebar is hidden is derived, 19 + 3 · 14 + 2 · 9 + 9 = 88 (one light gap after the zoom button); its show-sidebar button sits there and the first item `SM + CONTROLS` later (120); fullscreen uses `CANVAS`. During a sidebar motion ADR-0030's Panels rule moves them.
- **M3, bars:** every bar centres its items; the top rows hold SM 24 pills and buttons and MD 28 segmented tracks, and both end their last control `CANVAS` from their trailing edge (the sidebar's toggle, an SM button, ends at W − 12, so its 16 pt icon box ends at W − 16).
- **C1, card columns** (from the card's inner left edge): the 4 pt change bar, then the number columns, each right-aligned in a `digits · advance` cell: `gutter(digits, advance, columns) = max(GUTTER_MIN, ceil4(CHANGE_BAR + NUMBER_PAD_L + columns · digits · advance + (columns − 1) · NUMBER_GAP + NUMBER_PAD_R))`, one minimum and one `ceil4` over the total; `columns` is 1 for a one-sided card and for each split half, 2 for unified (old, then new, `NUMBER_GAP` apart). At 13 pt (advance 7.8): one column 40 up to 3 digits (39.4), 48 for 4, 56 for 5, 64 for 6; unified 72 for 3 digits, 88 for 4. Code starts at `gutter + CODE_PAD` in bars and none modes (50 for a one-column gutter up to 3 digits; 82 unified at 3 digits); in `+-` mode the indicator's cell (2 advances, it holds a code glyph) replaces `CODE_PAD`, so code starts at `gutter + 2 · advance` (55.6 at 13 pt, 3 digits).
- **C2, file header:** the chevron's 16 pt box at `CHEVRON_X` 12 (its chevron-down ink lands 16.3 from the card's outer edge; the reference's at 15.5); the path at `PATH_X` 40 in every card (paths align across cards; in a one-column card with ≤ 3-digit numbers it meets the gutter's end); trailing controls end `CARD_TRAILING` 8 from the inner right edge. Section bands put their chevron box at `CHEVRON_X` and their label at `PATH_X` from the card column's inner edge, so they align with file headers; gap-row links start at the code column, `GROUP` apart.
- **C3, header card:** avatar at `CARD_X` 16, `AVATAR_LG` = `CODE_X − CARD_X − CONTROLS` = 26, so the title's box starts at `CODE_X` 50: the code column of a one-column or split card up to 3 digits in bars or none mode. Wider gutters, unified and `+-` cards start their code further right; the title stays at 50. Height `CARD_Y + 20 + 18 + CARD_Y` = 54, plus its two borders = 56.
- **C4, inline blocks:** thread blocks and the composer sit `NESTED_X` 12 from the card's inner edges and `NESTED_Y` 8 apart vertically, radius MD; their content sits `COMPACT_X` / `COMPACT_Y` inside them. A code snippet or suggestion inside a comment uses the card's column formula from its own frame's inner edge (numbers in `card::gutter(digits, advance, 1)`, code at `gutter + CODE_PAD`: 50 for 3 digits at 13 pt); it does not align with the diff's columns, since it sits inside a nested card.
- **S1–S4, sidebars:** fields, row highlights and cards sit `SIDEBAR` 10 from both edges (filter field, find input, tree, Reviews, accordion headers, find results, threads-panel cards). Inside a highlight or field, the leading icon box (`ICON_SM` in rows and fields, `ICON_XS` for a disclosure chevron) sits at 10 + `ICON_LEAD` = 16 and leading text without an icon at 10 + `TEXT` = 18; trailing icon boxes end at W − 16 and trailing text at W − 18. Plain text outside a highlight (the footer) sits on the `SIDEBAR` edge 10. The filter field's top is `TOP + RIM` = 54.
- **Tree rows:** at depth n (x₀ = n · `TREE_INDENT`), the chevron's 12 pt box at 16 + x₀, the folder or file icon's 14 pt box `INLINE` after it (32 + x₀), the label `ICON_LABEL` after that (52 + x₀). A file keeps the chevron's slot empty, so the files and folders of one depth share the icon and label columns. An accordion header puts its chevron box at 16 and its label `ICON_LABEL` after it (34).
- **Scaling:** geometry that holds code text scales with the code row (rows; file header `row + 24`, 44 at 13 pt; gap row `row + 12`; placeholder `2 · row + 8`); geometry that holds UI text is fixed points (bands, pills, Viewed, icons, insets). `CARD_TRAILING` is fixed: it does not follow the header's height.
- **No layout shift:** changing numbers in the UI font (`N/M`, thread and draft counts, footer totals) use tabular figures or the code font; selected, hover, focused and pressed states change color only, never weight, width or padding; conditional items have reserved slots or overlay.

### Where tokens live and how they are enforced

- `polygloss_viewport::space` (the viewport paints the canvas and cards, and the app depends on it): the semantic tokens, card columns and functions, text tokens and strokes, with invariant tests. Each group module exposes `ALL`: `&[(&str, f32)]`, and `&[(&str, (f32, f32))]` for `text`. Call sites write module-qualified paths (`height::SM`, `radius::SM`; groups are not glob-imported). `CardStyle::default()`, `Metrics::default()` and every viewport geometry constant read from it. `polygloss_app::space` re-exports it and adds `layout`: app-only sizes (top-row and panel widths, minimum widths, picker, menu and dialog sizes, Home columns, toolbar give-way caps, the tree's Viewed slot). gpui-base's `SpacingTokens` and `RadiusTokens` are not used.
- gpui-component: radius SM, `radius_lg` LG; Buttons `.xsmall()` (20, at `radius::XS`) or `.small()` (24) only; kit internals (Button, Input, ListItem, PopupMenu) keep their rem metrics at the pinned 16.
- `tests/scripts/spacing-tokens.test.ts` scans every `.rs` file `rg --files` lists under `crates/polygloss-app/src` and `crates/polygloss-viewport/src` (untracked files included). It strips comments and `#[cfg(test)]` items by brace matching (a `#[cfg(test)] mod x;` declaration strips only itself) and the token modules the same way: both `space.rs` files, and the `tokens` and `ink` modules of the motion modules (motion's rendering code is scanned). Identifiers are matched by `_`-separated component. Rules:
  1. A literal dimension: a number as the whole argument of `px`, `rems`, `relative`, `Pixels::from` or `Pixels(` (except 0), a number with `.into()`, and any numeric literal other than 0, 1, 2 or 0.5 inside one of those calls.
  2. gpui rem spacing, size, inset, radius and border-width helpers (`p_2`, `gap_1p5`, `size_4`, `top_1`, `rounded_md`, `border_2`); `_0`, `_full`, `_auto`, fractions, `min_w_0`, `min_h_0` and `border_1` (`BORDER`) pass.
  3. Every `text_*` size preset (`text_xs` … `text_3xl`, `text_base`) and any `line_height(` outside the text helper.
  4. Numeric consts and statics of `f32`, `Pixels`, `Size`, `Point`, or tuples and arrays of them (`WINDOW_SIZE: (f32, f32)`), and a `let` binding of a numeric literal other than 0, 1, 2 or 0.5.
  5. A struct-literal field set to a number whose name has a geometry component (`margin`, `gap`, `radius`, `pad`, `padding`, `height`, `width`, `inset`, `offset`, `border`, `size`, `indent`): `margin_x`, `card_gap`, `pad_bottom`, `row_height`, `header_height`, `border`.
  6. In every viewport `src` file, float literals other than `0.0`, `1.0`, `2.0` as a divisor and `0.5` as a factor, except as arguments of `hsla`, `rgba`, `.alpha` and `.opacity`.
  7. A `Button::new(` chain without `.small()` or `.xsmall()`, and an `.xsmall()` chain without `.rounded(px(radius::XS))`.
- The allow-list is path + exact snippet + reason (non-geometry consts and ratios, `perf/`, `dump.rs`); an entry that no longer matches fails. Failures read `path:line rule 'snippet' → space::<group> (ADR-0031)`, and for the debt map `spacing-debt.json[path]: N → M`. The lint is a text scan: a dimension built from non-literal arithmetic outside the token modules is a review finding, not a lint failure.
- During M7 a per-file debt map ratchets: a file fails above its debt and below it, so each migration lowers the number. At each wave merge it is re-seeded (`UPDATE_SPACING_DEBT=1`), and the merge fails if any entry rises. M7's last task deletes the map.
- Invariant tests assert rules against independent sources: the grid, the probe's ladder, concentric radii; the lint parses each group's `pub const` names and fails if one is missing from that group's `ALL`. They never restate token values.
- **Reference tests** take their origins (the window's, sidebar's and main column's edges, each card's outer edge) from layout bounds: app debug selectors and the viewport's debug frame, never ink. The default theme's card border (`#e7e7e7` on `#f8f8f6`) and divider (`#e7e7e7` beside `#ebebea`) differ from their backgrounds by 17 and 4 per channel, under any glyph threshold. Ink (a pixel more than `threshold` per channel off the local background; 24 unless the test passes another) measures only glyphs and icons. Fixtures start with the reference's own glyphs (`internal/diff/diff.go`, `init`, `//`, `godiff`, `Filter files`, `internal`, `diff`, `Total:`), so both inks include the same letter's side bearing. Each test asserts `abs(measured − reference) ≤ allowed + 0.5` (the measurement's accuracy), with both numbers written in the test from the table below. `CardStyle::default()` and `Metrics::default()` are pinned to the reference's numbers at 13 pt (side margin 12, gap 12, file header 44, change bar 4).

## Consequences

- Every screenshot baseline changes; the M7 spacing tasks re-record theirs and the gate reviews all of them against the reference.
- The card's inner width changes, so the automatic split/unified threshold (160 ± 8 columns) is reached at different window widths; anchor tests and the §12.1 budgets are rerun. Header and band columns stop scaling with the code font.
- UI text gets even line heights instead of gpui's 1.618 default, so most single-line controls change height by a fraction of a point.
- The two segmented controls become one component; thread blocks, the composer and suggestion snippets reuse the card's gutter function instead of their own formulas.
- The reserved banner strip (OQ-39) and the tree's Viewed slot (OQ-43) keep their approved behavior; the alternatives are shown to the user at the M7 gate, with OQ-56's answer.
- The lint covers the literal forms it names, with a fixture for each; arithmetic on non-literal values is left to review.

## Alternatives rejected

| Option                                                | Why not                                                                                               |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| gpui-base `SpacingTokens` / `RadiusTokens`            | No 6, 10 or 28 steps; the kit's components do not read them                                           |
| gpui rem helpers as the scale                         | They follow `Theme.font_size`; at a native 13 every value turns fractional (× 0.8125)                 |
| A primitive scale (`S1`, `S2`, …) under the tokens    | Call sites may not use it and the tokens are written as values, so it is an unused layer              |
| A strict 8 pt grid                                    | Breaks AppKit's 20/28/36 and the reference's 12 pt gaps                                               |
| Pixel-matching the reference (13, 22, 30, 41.5, 56.5) | Odd values with no rule; each deviation is ≤ 2 pt and recorded above                                  |
| One ink column for every sidebar icon                 | Lucide's ink insets differ by glyph (0.6–5.3 pt); boxes are the column, ink is recorded               |
| Origins measured as ink                               | A 1 pt border 17 off its background is below any glyph threshold; the round-1 audit missed it by 1 pt |
| A "canvas lead" token                                 | The banner strip is the canvas above the first card; cards start at its bottom edge                   |
| 0.5 pt hairlines                                      | The reference's borders are 1 pt; half-point quads blur at 1×                                         |
| 44 pt hit targets                                     | A pointer-only macOS app; AppKit's regular control is 24 pt                                           |
| Header and band columns in code-font advances         | Fractional columns, and chrome that moves with the code font                                          |
| Per-crate token sets                                  | The app's header card, thread blocks and composer mirror geometry the viewport paints                 |
| A lint in Rust (build script, clippy)                 | The repo's hygiene guards are bun tests; a text scan with fixtures is simpler                         |
| Shrink the banner strip now                           | Reverses D4 ("content never moves"); the user decides (OQ-39)                                         |
| A density setting                                     | Not asked for; the tokens make it possible later                                                      |
